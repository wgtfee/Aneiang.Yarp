# Industrial Gateway Service Health V0.7 交付说明

## 已实现

- Gateway 自身健康契约：`/healthz`、`/health/live`、`/health/ready`。
- 后端 API 路由：IAM、MOL、IoTSharp、WCS、ThingGetWay；业务入口路由：`/mes/*`、`/iot/*`、`/wcs/*`、`/thinggateway/*`。
- ThingGetWay（设备采集网关）使用 `http://localhost:5000`，API 入口为 `/api/thinggateway/*`，并统一提供 `/health/live`、`/health/ready`、`/healthz`。
- YARP Active/Passive Health Check，运行时状态从 `IProxyStateLookup` 读取。
- 健康聚合 API：`GET /platform/api/operations/health-summary`，包含按 `healthRole` 分组的统计。
- 完整配置快照：`GET /platform/api/operations/snapshot`，包含 Route 与 Cluster。
- 健康历史 API：`GET /platform/api/operations/health-history`。
- 健康变化 SignalR：`/{dashboardPrefix}/hubs/health`，事件名 `HealthStatusChanged`。
- 多 Destination 负载均衡及蓝绿切换 API：
  `POST /platform/api/operations/blue-green/{clusterId}/switch`。
- SQLite 健康历史迁移 `010_service_health_history`，只记录状态变化，避免探针高频写入。
- 设备健康与主机健康隔离：Gateway 只判断 ThingGetWay 服务 Destination，不计算 PLC、采集驱动或遥测状态；设备在线状态仍由 ThingGetWay 自己负责。
- ThingGetWay 已接入 `Industrial.Security`：本地 `SysUser.PermissionCodeList` 与旧 `RolePermission` 保留，中央模式使用 IAM JWT/权限快照；权限 Manifest 为 `ThingGetWay/src/ThingsGateway.Server/permission-manifest.json`，通过 `appsettings.Centralized.json` 开启。

## 蓝绿约定

Destination 名称应包含 `blue` 或 `green`，例如 `mes-blue-1`、`mes-green-1`。切换时请求：

```json
{ "targetSlot": "green" }
```

切换是一次动态 Cluster 更新，立即发布到 YARP，不需要重启 Gateway 或业务系统；配置历史仍可用于回滚。

## 验证

执行 `tests/V07-HealthSmoke.Tests.ps1 -RequireDashboardApi` 可验证健康端点、ThingGetWay 集群、快照、健康聚合和健康历史接口。脚本默认访问 `http://localhost:5202`，可通过 `-BaseUrl` 指定其他地址；需要自定义集群时传入 `-ExpectedClusters`。

## 回滚

1. 使用控制台配置历史恢复最近一次 Gateway 配置快照；或调用现有配置回滚 API。
2. 蓝绿切换失败时，重新调用切换 API 指向原 Slot。
3. 健康历史保留在 `gateway-store.db`，不会修改 IAM、MOL、IoTSharp、WCS 的业务数据库。
